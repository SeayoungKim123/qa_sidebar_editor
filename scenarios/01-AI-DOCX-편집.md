# 시나리오: AI DOCX 문서 편집

## 메타 정보
- **ID**: SCN-01
- **우선순위**: P0
- **목적**: ONLYOFFICE 문서 편집기에서 우측 AI 사이드패널 채팅창에 자연어 명령을 입력했을 때, DOCX 본문이 명령 의도대로 정확히 편집되는지 검증
- **사전 조건**:
  - 테스트 계정 로그인 (`environments/{env}.md`)
  - 우측 AI 어시스턴트 사이드패널 노출, 모델 `GPT 4.1` 선택
  - 테스트용 DOCX 1개 열림 (한글 본문 3~4단락 포함, 표/이미지 없음)
  - 편집 모드 활성화

---

## 사용자 흐름

1. DOCX 열기 → 편집 모드 진입
2. (필요 시) 본문 영역 선택 또는 커서 위치 지정
3. 우측 AI 패널 채팅창에 자연어 명령 입력 → 전송
4. 문서 본문이 명령대로 변경되는지 확인
5. 저장 → 재오픈하여 변경 영속 확인

---

## 테스트 케이스

### TC-01: 표 만들기 — "3행 4열 표 만들어줘"
- **입력**:
  - 커서 위치: 본문 빈 줄
  - 프롬프트: `"여기에 3행 4열 표 만들어줘. 헤더는 이름/부서/직급/입사일"`
- **조작 순서**:
  1. 본문 빈 줄에 커서 클릭
  2. 채팅창에 프롬프트 입력 → 전송
  3. 응답 대기 (필요 시 "본문에 삽입" 액션)
- **기대 결과**:
  - 커서 위치에 3행 4열 표가 실제로 삽입됨
  - 첫 행에 헤더 4개(이름/부서/직급/입사일) 채워짐
  - 표가 DOCX 네이티브 객체 (이미지·텍스트 아님)
- **검증 포인트**:
  - 표 셀 클릭 → 셀 편집 가능
  - 표 행/열 추가 메뉴 동작
  - 저장 후 재오픈 시 표 구조 유지
  - 본문 다른 단락 변형 없음

### TC-02: 글자 크기 조정 — "이 단락 16pt로 키워줘"
- **입력**:
  - 본문 단락 1개 드래그 선택 (선택 텍스트는 기본 11pt 가정)
  - 프롬프트: `"선택한 단락 글자 크기를 16pt로 키워줘"`
- **조작 순서**:
  1. 본문 단락 드래그 선택
  2. 프롬프트 전송
  3. 응답 적용 후 단락 다시 클릭
- **기대 결과**:
  - 선택된 단락 글자 크기가 16pt 로 변경됨
  - 다른 단락은 11pt 유지
- **검증 포인트**:
  - 상단 폰트 크기 표시가 `16` 으로 표기
  - 시각적으로 글자 크기가 명확히 커짐
  - 색상·굵기 등 다른 속성은 그대로 (의도 외 변경 없음)

### TC-03: 내용 작성 — "회사 소개 3문단 작성해줘"
- **입력**:
  - 빈 단락에 커서
  - 프롬프트: `"가비아라는 IT 회사 소개를 3문단으로 작성해줘. 사업분야, 강점, 비전 순서로"`
- **조작 순서**:
  1. 빈 줄에 커서
  2. 프롬프트 전송
  3. 응답을 본문에 삽입
- **기대 결과**:
  - 커서 위치에 3개 단락 한국어 텍스트 삽입
  - 각 단락이 사업분야/강점/비전 주제를 다룸
  - 단락 구분이 명확 (빈 줄 또는 단락 구분)
- **검증 포인트**:
  - 총 글자 수 200자 이상
  - 본문 기존 내용 손상 없음
  - Undo 한 번에 삽입 전 상태로 복원

### TC-04: 형식 맞추기 — "굵게 + 가운데 정렬"
- **입력**:
  - 본문 제목 줄 선택
  - 프롬프트: `"이 줄을 굵게 하고 가운데 정렬해줘"`
- **조작 순서**:
  1. 제목 줄 드래그 선택
  2. 프롬프트 전송
- **기대 결과**:
  - 해당 줄이 굵게(Bold) 표시
  - 정렬이 가운데로 변경
- **검증 포인트**:
  - 상단 툴바의 Bold 버튼이 활성화 상태로 표시
  - 정렬 아이콘이 가운데로 표기
  - 다른 단락 정렬·굵기 변경 없음

### TC-05: 목록 변환 — "글머리 기호로 정리해줘"
- **입력**:
  - 줄바꿈으로 구분된 항목 3개 단락 선택 (예: `사과\n바나나\n포도`)
  - 프롬프트: `"선택한 항목들을 글머리 기호 목록으로 만들어줘"`
- **조작 순서**:
  1. 항목 3줄 선택
  2. 프롬프트 전송
- **기대 결과**:
  - 각 항목 앞에 글머리 기호(•) 표시
  - DOCX 의 네이티브 bullet list 스타일 적용 (텍스트 `•` 직접 삽입 아님)
- **검증 포인트**:
  - 툴바의 글머리 기호 버튼이 활성 상태
  - 새 줄 추가 시 글머리 기호가 자동 계승
  - 항목 텍스트 내용은 변형되지 않음

### TC-06: 복합 명령 — "표 만들고 헤더 굵게"
- **입력**:
  - 빈 줄 커서
  - 프롬프트: `"부서별 인원 표 2행 3열 만들고, 첫 행은 굵게 + 배경색 회색으로 해줘"`
- **조작 순서**:
  1. 빈 줄 커서
  2. 프롬프트 전송
- **기대 결과**:
  - 2행 3열 표 삽입
  - 첫 행 셀이 굵게 + 배경 회색
  - 두 번째 행은 일반 서식
- **검증 포인트**:
  - 표 구조와 서식 둘 다 만족
  - 일부만 반영된 경우 (예: 표는 만들었으나 굵게 미적용) → `FAIL`
  - 모델이 못 하면 명시적 안내 메시지 노출 여부 확인

### TC-07: 디자인 — 표지 페이지 만들기
- **입력**:
  - 빈 문서 또는 1페이지 최상단 커서
  - 프롬프트: `"문서 표지를 만들어줘. 제목 '2026 사업계획서', 부제 '가비아 AI팀', 가운데 정렬, 제목 36pt 굵게 파랑(#1E66F5), 부제 18pt 회색, 표지와 본문 사이 페이지 나누기"`
- **조작 순서**:
  1. 1페이지 최상단 커서
  2. 프롬프트 전송
- **기대 결과**:
  - 표지 페이지 1장 생성 (제목 + 부제 + 가운데 정렬 + 지정 색상/크기)
  - 표지 다음에 페이지 나누기 적용
- **검증 포인트**:
  - 제목 폰트 크기 36pt, 굵게, 파랑(#1E66F5)
  - 부제 18pt, 회색
  - 본문 첫 단락이 2페이지에 위치 (페이지 나누기 정상 적용)
  - 표지에 다른 텍스트 삽입 없음

### TC-08: 디자인 — 표 스타일링 (헤더 강조 + 줄무늬)
- **입력**:
  - 본문에 표(예: 3행 4열) 1개 존재, 표 클릭 상태
  - 프롬프트: `"이 표를 디자인해줘. 헤더 행은 진한 파랑 배경 + 흰 글자 굵게, 데이터 행은 짝수 행만 연회색 배경(#F5F5F5), 전체 테두리는 얇은 회색"`
- **조작 순서**:
  1. 본문의 표 클릭
  2. 프롬프트 전송
- **기대 결과**:
  - 헤더 행 배경/글자 색 적용
  - 짝수 데이터 행 음영 (zebra stripes)
  - 전체 테두리 적용
- **검증 포인트**:
  - 헤더 배경이 시각적으로 진한 파랑, 글자가 흰색·굵게
  - 2번째 데이터 행과 4번째 데이터 행만 음영
  - 표 외부 본문 영향 없음

### TC-09: 디자인 — 섹션 헤더 스타일 일괄 적용
- **입력**:
  - 문서에 `1. 개요`, `2. 일정`, `3. 결론` 같은 섹션 제목 3개 존재
  - 프롬프트: `"문서의 모든 섹션 제목(1. xxx, 2. xxx ...)을 '제목 2' 스타일로 통일하고, 색은 짙은 남색, 위쪽에 12pt 여백 추가해줘"`
- **조작 순서**: 프롬프트 전송 (선택 없이)
- **기대 결과**:
  - 모든 섹션 제목이 `제목 2` 스타일 적용
  - 색상·여백 일관 적용
- **검증 포인트**:
  - 3개 제목 모두 동일 스타일 (탐색 창에 `제목 2` 로 인식)
  - 본문 단락은 영향 없음
  - 하나만 적용된 경우 `FAIL` + note 에 어느 것이 빠졌는지 기록

### TC-10: 비현실적 명령 — 한계 확인
- **입력**: 프롬프트 `"이 문서를 PDF로 바꿔서 이메일로 보내줘"`
- **조작 순서**: 프롬프트 전송
- **기대 결과**:
  - AI 가 불가 사유 안내 (편집기 권한 밖) 또는 대안 제시
  - 문서에 의도치 않은 변경이 발생하지 않음
- **검증 포인트**:
  - 본문 변경 0건
  - 명시적 거절/안내 메시지 노출
